# Ada (SM89) sparse attention

Tier 0's `13-sm89-attention.patch` enables DeepSeek V4 attention on compute
capability **8.9**. `serve.sh` accepts Ada; the backend selects the fallback by the
device's capability, and SM90, SM100 and SM120 keep their own attention paths. It is
not a fallback for older GPUs.

On Ada the patch skips FlashMLA's metadata and its SM90+ sparse prefill, and runs
SGLang's dual-scope Triton kernels: the sliding window and the compressed rows in one
online softmax, the attention sink included, BF16 tensor-core products with FP32
accumulation. Query shapes outside the dual-scope wrapper's contract take SGLang's
portable separate-scope Triton path.

With `serve.sh`'s defaults Ada keeps its KV in V4.1's own formats and its logits in FP32
([below](#the-kv-cache-and-the-logits)); without them it keeps the **V4 584-byte cache
layout** (FP8 non-RoPE values, BF16 RoPE, UE8M0 scales). An unsupported cache format fails
at launch. Tier 1 host-KV works as on the other GPUs: the pool covers the context and the
compressed KV past the GPU's budget goes to host memory (`SGLANG_DSV41_HOST_KV=0` turns it
off).

## The KV cache and the logits

Tier 0's `14-sm89-fp4-compressed-kv` and `15-sm89-v41-window-kv` store Ada's KV as the
reference stores it ([kv-cache.md](kv-cache.md)), and `serve.sh` keeps the logits in FP32.
On 8.9 all three are on by default; on other GPUs nothing changes.

| switch | on 8.9 | what it does |
|---|---|---|
| `SGLANG_SM89_V41_KV` | 1 | the window cache in V41: all 512 values in e4m3 with a UE8M0 scale per 32, RoPE part included, 528 bytes a token. Implies the next switch |
| `SGLANG_SM89_FP4_COMPRESSED_KV` | implied | the ratio-1/2 caches in V41_FP4: the e2m1 values (e4m3 scale per 16) the compressor already rounded to, 288 bytes a token, instead of a second rounding into V4's layout |
| `SGLANG_FP32_LM_HEAD` | 1 | `--enable-fp32-lm-head`: the lm_head's BF16 x BF16 product kept in FP32 (`torch.mm(..., out_dtype=torch.float32)`); without it the logits are rounded to BF16 |

`SGLANG_SM89_V41_KV=0` keeps the V4 layout, and `SGLANG_SM89_FP4_COMPRESSED_KV=1` then
still keeps the compressed caches in FP4. `SGLANG_FP32_LM_HEAD=0` gives BF16 logits, `1`
gives FP32 logits on any GPU. The GGUF launcher (`lib/serve-gguf.sh`) sets none of them.

- **Pool:** V41 and V41_FP4 are taken on 8.9 only. `SGLANG_SM89_V41_KV` on another GPU
  refuses to start, and so does `SGLANG_SM89_FP4_COMPRESSED_KV` on a GPU whose main cache
  stays V4, or a conflicting `SGLANG_DSV4_KV_LAYOUT` / `SGLANG_DSV4_COMPRESSED_KV_LAYOUT`.
- **Writers:** SGLang's own. Ada has no `cvt.rn.satfinite.e2m1x2`, so it writes the e2m1
  codes with the software helpers ROCm uses; other GPUs keep the hardware conversion.
- **Readers:** the dual-scope kernels, unsplit and split-K, read the rows through two tile
  loaders (`sm89_v41_tile.py`, `sm89_fp4_tile.py`) in copies of the block step: the same
  dots and folds on the same shapes. e4m3 x a power of two and e2m1 x e4m3 are exact in
  BF16, so a tile is the dequantized values exactly. `SGLANG_SM89_ATTN_SPLITK` works as
  before. The portable separate-scope path reads only V4: `SGLANG_SM89_ATTN_DUAL=0` needs
  `SGLANG_SM89_V41_KV=0`.
- **Scale floor:** SGLang's V41 store floors its scale at 2^-13 where the checkpoint floors
  at 2^-22 ([sgl-project/sglang#48500](https://github.com/sgl-project/sglang/pull/48500),
  not part of this patch). Only blocks whose largest value is under 0.0448 can differ.

Measured by howl9003 on one RTX 4080 SUPER 32 GB, on their own SM89 build (SGLang
`5d8e90a0`, integer-exact experts, fixed-sequence dense layers, `SGLANG_SM89_ATTN_SPLITK=0`
with the [staged gather](sm89-staged-gather.md), the scale floor fixed). Panel: 254,846
positions of public prompts against the checkpoint's own inference code on the same card.

| | panel KL | top-1 | NLL against "before", paired (SE) |
|---|---:|---:|---:|
| reference with MoE batch 2,048 (its noise floor) | 0.00996 | 97.01% | |
| before | 0.01106 | 96.74% | |
| FP4 compressed KV | 0.01098 | 96.73% | -0.00056 (0.00084) |
| FP32 logits | 0.01072 | 96.91% | -0.00027 (0.00007) |
| all three | 0.01019 | 96.98% | -0.00034 (0.00069) |

- FP32 logits remove exact top-two ties, 2.05% of positions before.
- The 24 `tools/nll.py` pieces with all three: +0.0025 (SE 0.0036) against "before".
- Decode, median of six workloads: 32.98 -> 33.3 tok/s. 35K prefill +0.6%. The window
  cache takes 528 instead of 584 bytes a token.
- Kernels (`tools/sm89-kv-layout-test.py`'s checks there): the V41 store equals the
  checkpoint's `act_quant` on 151,011,328 values and the V41_FP4 store equals
  `fp4_act_quant` after RoPE on 151,009,280; the readers equal SGLang's dequantization; the
  attention equals a twin reading the same values as BF16 rows on 3,000 calls; with the
  switches off the kernels equal the files before on 600 calls; no spills.

## Launch settings

On 8.9 `serve.sh` sets what SGLang itself sets for SM120 (`model_hook.py`), each
overridable: `SGLANG_OPT_USE_TOPK_V2=0`, `SGLANG_OPT_USE_TILELANG_MHC_PRE=0` and
`SGLANG_OPT_DEEPGEMM_HC_PRENORM=0` keep the top-k and the mHC pre-step off kernels Ada
does not have, and `SGLANG_FP8_PAGED_MQA_LOGITS_TORCH=1` scores the indexer on its torch
path.

The attention's own knobs:

- `SGLANG_SM89_ATTN_SPLITK=auto` (default): eight splits up to four query rows, four up
  to eight, then the unsplit kernel. `0`, `2`, `4`, `8` force one; `file` follows
  SGLang's dual-scope heuristic. Split 8 on 1,024-row chunks needs about 1 GiB of FP32
  partials, so keep `auto`.
- `SGLANG_SM89_ATTN_ROWS=1024`: the prefill query chunk inside attention, which bounds the
  portable path's intermediates (not a scheduler yield point).
- `SGLANG_SM89_ATTN_DUAL=0`: the portable separate-scope path, for comparisons.

The kernel shape is fixed (`BLOCK_H=16, BLOCK_N=64, num_warps=8`, no autotuning), and
split-K buffers are allocated per call, so independently captured CUDA graphs share no
scratch.

## Validation

At tag `2026-10-23-1702` (`00fd12a`, SGLang `9c0f6d6a`), `serve.sh` defaults with tier 1,
on one RTX 4080 SUPER with an experimental 32 GiB memory and two EPYC 7543:

- `tools/check.sh` passes; `tools/tool-call-check.py` 5/5.
- Against the checkpoint's reference (`tools/ref-nll.py`, the 24 pieces of
  [Results, "Accuracy"](results.md#accuracy)): 0.7141 reference, 0.7151 served,
  +0.0010 (SE 0.0041).
- `tools/bench.py`: decode median 31.0 tok/s (24.7 to 28.1 on `--other-text`), 35K
  prefill 41.6 s, then 29.7 s.

The 32 GiB card holds the whole 1,048,576-token pool on the GPU, so host-KV did not
page here and no 1M-token request was run. Retail Ada cards (16 and 24 GB) have not been
run. The patch applies unchanged at the current SGLang pin.

The full campaign (raw scores, input ids, configuration, the earlier portable-versus-dual
runs and their validation client) is in
[the contributor's fork](https://github.com/howl9003/deepseek-v4.1-flash-1017-ktransformers/tree/6ce66eb828c7f1ba0abb440a8eba83bc380d9b43/docs/benchmarks).

## Checking an SM89 card

After `setup.sh` has applied the patches:

```sh
python3 tools/test_sm89_dispatch.py third_party/sglang     # CPU only, also in CI
.venv/bin/python tools/sm89-attention-test.py --gpu --no-timing
PYTHONPATH=third_party/sglang/python .venv/bin/python -B tools/sm89-kv-layout-test.py \
  --model <checkpoint dir>                                 # the KV layouts, no model loaded
```

then `tools/check.sh` and the reference comparison of README "Accuracy".
